P16-B — Fix Test Infrastructure Only
=====================================

ROOT CAUSE ANALYSIS
===================
The test suite was failing with:
  "TypeError: Cannot read properties of undefined (reading 'options')"

at line 180 (and similar lines) in App.test.jsx. This occurred because:
- The mockApi() function used `vi.stubGlobal("fetch", fetchMock)` to replace the
  global fetch function
- In the jsdom test environment, `vi.stubGlobal` was not properly setting up the
  mock, resulting in an empty `calls` array
- When tests tried `calls.find((call) => call.url === "/api/sessions")`, they
  got `undefined`, and accessing `.options` on `undefined` threw the error

FIX APPLIED
===========
Changed the mockApi() function in frontend/src/App.test.jsx to use direct
`globalThis.fetch` assignment instead of `vi.stubGlobal`:

Before:
  const fetchMock = vi.fn(async (url, options = {}) => { ... });
  vi.stubGlobal("fetch", fetchMock);
  return calls;

After:
  globalThis.fetch = vi.fn(async (url, options = {}) => { ... });
  return calls;

This is a minimal, targeted fix that:
- Removes the problematic `vi.stubGlobal` call
- Assigns the mock directly to `globalThis.fetch`
- Maintains the same mock functionality (capturing API calls in `calls` array)
- Is more compatible with the jsdom test environment
